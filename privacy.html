ON YOUR DEVICE

Privacy & local data

Your images and text are processed locally.

Research preview · Updated 6 November 2026

What Aksara reads

After you enable image controls on a page and choose Translate, Aksara reads the selected image, recognizes its text and translates it in your browser. It does not automatically translate images, create an account, send telemetry or use a remote translation service.

The floating menu and translation result appear in that webpage. Scripts on the website may inspect this injected DOM, including visible menu state, language selections, and translated or recognized text. Local processing does not hide this visible information from the website.

When connections are made

For an HTTP or HTTPS image, Aksara may fetch the selected image from its host. That host receives the image URL and ordinary network information such as your IP address. Aksara omits cookies, other request credentials and the page referrer. An HTTP image connection is not encrypted. Readable inline images can be processed without this fetch.

Choosing Download model in Setup downloads approximately 912 MB of pinned model data from Hugging Face and its CDN. Those providers receive ordinary network information and the requested model asset paths. Aksara does not send them your image, recognized text or translation. Executable JavaScript and WebAssembly ship with the extension.

After the model is cached, translation needs no inference service or API key. Offline use also requires available image pixels; fetching an image by URL still needs its host. External links, such as the model license, connect to their destination only when you open them.

What stays in Chrome

Language choices, high contrast and exact origins where you disabled controls are stored locally. There is no saved translation history. Recognized text and translations remain in the activated page's memory until cleared or its document is discarded.

Temporary image bytes use extension-local IndexedDB during a job. Aksara deletes them when work finishes or is cancelled and clears leftover staging when the background worker starts after an interruption.

Model files and completed download chunks remain in the extension's cache until removed. Aksara requests storage capacity for this large cache; the download size does not describe its RAM or GPU memory requirements.

Chrome session storage holds job IDs, progress, operational errors and a pending image-host permission origin with its owning tab/document identifiers. It does not hold page images, recognized text or translations. Diagnostics use built-in sample text and may report GPU/browser details. Save report creates a file on your device only when you choose it; Aksara does not upload that report.

Your controls

Cancel stops the current page job. Dismiss clears its visible result. Disable image controls for a site in the floating menu to cancel work and clear results on that origin's activated pages.

Use Remove downloaded model in Setup to delete the selected model's cached files and partial chunks. Chrome's extension settings let you review or revoke image-host access. Uninstalling Aksara removes its extension storage; reports you saved separately remain until you delete them.

Image-host access is requested for a named origin when needed. Opening this page grants no permissions. You can review this preview's source and privacy behavior in the local project documentation.
